01

Overview

What it is

Get Gym Done is a clickable hi-fi prototype of a workout-tracking Android app. The reference program comes from the user's own illustrated 5-day split PDF — Upper / Lower / Shoulders & Arms / Legs (Quad) / Back & Chest — and is preloaded with 26 exercises, form cues, and recommended sets & reps. The prototype is fully interactive: log real sets, swipe between exercises, watch progression charts update, and live-switch between four workout-screen layouts via the Tweaks panel.

Goals

  • One screen, one job. Each screen does one thing well — picking, logging, reviewing.
  • Big numerals, fast logging. Sweaty hands, between-set timing — large tap targets and pre-filled defaults from the previous session.
  • Calendar-first. The home screen is the calendar — the app picks the next day automatically but you can override on any tap.
  • Honest placeholders. Where real GIFs/anatomy art belongs, we show labeled striped placeholders rather than fake illustrations.
North star

"Open app → know what to lift → log it → leave." Anything that delays that loop is wrong. The huge "Complete Set" CTA is the most-used pixel in the app.

Component vocabulary

  • Striped placeholder. Used for exercise GIFs and any imagery we don't have — labeled in lowercase mono so it's clearly a placeholder.
  • Set row. Set number + weight stepper + reps stepper + done checkmark. Active state outlined in lime, done state filled with lime tint.
  • Pill chip. Two variants: solid (lime, for primary muscles) and outline (for secondary muscles, units, filters).
  • Cards. Surface 1 with thin line border. Hero cards switch to full lime fill for the "next-up" emphasis.
  • Bottom sheet. Used for keypad, day-override, exercise picker. Rises from bottom with 240ms cubic-bezier.
  • Big CTA. Bottom-pinned 22px-padded button in Anton 26pt. The Complete-Set CTA shows weight × reps inline so you can confirm before tapping.

05

Key flows in detail

Flow A · First-launch onboarding

  1. Splash
    Brand reveal. CTA "Let's Lift →" advances.
  2. Pick a split
    5 split options shown. The user's PDF split is tagged "From your PDF" and pre-selected. Day chips preview what each day looks like.
  3. Choose a method
    "Curate for me" loads the 26 exercises from the PDF and skips step 4. "Build my own" continues.
  4. Customize routine (optional)
    Day tabs (D1–D5). Each row is an exercise with a small GIF placeholder, primary muscle, prescription. Tap "Add exercise" to open the picker.
  5. Picker sheet
    Bottom sheet with muscle filters and the full exercise library. Each row shows a mini muscle map highlighting what it hits. Multi-select.
  6. Lock it in →
    Drops the user into Home with day 1 queued.

Flow B · Daily workout session

  1. Open app — Home
    App reads the workout log and computes the next day in the rotation. The big lime "Up next" card shows it. Tap "Start workout" to skip overview, or tap the side icon to open day overview.
  2. Optionally — Day overview
    Two tabs: Exercises (preview of all the day's lifts with prescriptions) and Warmup (recommended primer for the muscles being trained).
  3. Active workout
    First exercise opens. GIF, name, muscle map, prescription, form cues, and set rows are all visible. Layout depends on the user's Tweaks setting (Stacked is default).
  4. Log a set
    The "current" set is outlined in lime. Adjust weight (±2.5 kg) or reps (±1) with the stepper buttons, or tap the number to open the keypad. Tap the huge "Complete Set N" CTA to log it.
  5. Rest timer
    A 90s countdown bar appears at the top after each completed set. Skip with one tap.
  6. Next exercise
    After the last set of an exercise, the CTA becomes "Next exercise →". The progress dots at the top fill in.
  7. Add a set if needed
    Dashed "+ Add set" button below the set list lets the user extend on the fly. New set inherits the previous set's weight and reps.
  8. Workout complete
    After the last exercise's last set, the celebration screen appears with PR + volume callouts.

Flow C · Override the planned day

  1. From Home
    Tap the swap icon on the Up-next card, OR tap any other day in the "This week" list.
  2. Override sheet
    Bottom sheet lists all 5 days with the current one tagged. Pick another to switch.
  3. Active workout opens
    Workout loads the chosen day's exercises. The log will record whichever day was actually performed, not the originally queued one.

Flow D · Reviewing progress

  1. Profile tab
    Header with name, height, sessions. Two big stats: total volume, PRs this month.
  2. Exercise progression
    Default chart is Incline Smith Press. Tap any chip below to switch to another exercise. Current PR + 8-week % delta callout.
  3. Bodyweight
    Same chart treatment, coral accent. 8 weeks of weekly weigh-ins.
  4. Consistency heatmap
    7×8 grid of the last 8 weeks. Lime cells = trained, neutral = rest. Summary line with sessions, avg/week, streak.
  5. Recent PRs list
    Last few personal records with how long ago.

Workout layout variants

The active-workout screen is the highest-traffic surface in the app. We designed four variants in parallel — switchable live via the Tweaks panel — so the user can pick the approach that fits their training style. The variant is a global preference (set once, applied to every exercise).

Default
Stacked
Classic vertical scroll. GIF on top → name → muscle map → form cues → set tracker. Familiar for first-time users.
Minimal
Focus
110px-tall numerals dominate. Weight × reps with tap-to-edit. Form cues collapse behind a single chevron toggle. For experienced lifters.
Form-first
Coach
One form cue at a time in a giant lime card. Swipe through cues like flashcards. For users learning new lifts.
Dense
Compact
Everything in one scroll-free screen. 2×2 cue grid, compact set rows. For users who just want to log fast.

Next-day computation

The home screen reads the last log entry and queues (lastDay % 5) + 1 as the next workout. After day 5, the rotation wraps back to day 1. The user can override this on any tap, and the override is what gets logged.

File structure

Get Gym Done.html // entry — loads everything in order Get Gym Done — Offline.html // standalone single-file build Get Gym Done-print.html // PDF export page ───────────────────────── styles.css // global tokens, components, themes data.js // SPLIT_OPTIONS, EXERCISES, WORKOUT_DAYS, history ui.jsx // Icons, TabBar, TopBar, LineChart, MuscleMap tweaks-panel.jsx // useTweaks hook + Tweak* controls onboarding.jsx // Splash, SplitSelect, MethodSelect, CustomizeRoutine home.jsx // HomeScreen, DayOverview, SwitchDaySheet workout.jsx // WorkoutSession + 4 Layout* variants + SetRow + KeypadSheet profile.jsx // ProfileScreen with charts & heatmap settings.jsx // SettingsScreen, SettingsGroup, SettingsRow app.jsx // App — state machine, screen routing, tweaks wiring

Components are exported to window at the bottom of each file (Babel scope-per-file workaround). Load order in Get Gym Done.html matters — data.js must run before any consumer, and app.jsx must be last.

10

How to extend

Add a new exercise

  1. Add the entry
    In data.js, add a new entry to EXERCISES with id, name, primary[], secondary[], and cues[].
  2. Reference it in a day
    In WORKOUT_DAYS, add {id, sets, reps} to one of the day's exercises arrays.
  3. Optional: history
    Add an entry to EXERCISE_HISTORY and LAST_WEIGHT so the chart and pre-fill work.

Add a new workout-screen variant

  1. Write a new Layout* function
    In workout.jsx, model on LayoutStacked. It receives one props object with all session state and callbacks.
  2. Register it
    Add to the variant switch inside WorkoutSession and to the TweakSelect options in app.jsx.
  3. Export
    Include the new function name in the Object.assign(window, {...}) at the bottom of workout.jsx.

Hook up real persistence

All "log" mutations (completing a set, finishing a workout) currently update React state and in-memory data only. To productionize:

  • Replace the in-memory WORKOUT_LOG, EXERCISE_HISTORY, BODYWEIGHT with read/write methods against a local DB (Room on Android).
  • Wrap state updates in WorkoutSession.completeSet with a write call that records weight, reps, timestamp, and exercise id.
  • Charts in profile.jsx already accept any array of {date, weight} — point them at the live store.
  • Tweak preferences should be moved from the EDITMODE block to SharedPreferences/Datastore.

What's still placeholder

  • Exercise GIFs. Striped placeholders need to be replaced with real animated demos.
  • Muscle anatomy. The MuscleMap SVG is a stylized silhouette — fine for prototyping, but consider a real anatomical art system for production.
  • User profile photo. Currently a lime monogram chip ("AX").
  • Notifications, sync, exports. Settings rows exist but no logic.
11

Open questions for next iteration

  • Do we need supersets / drop sets / AMRAP support in the set tracker?
  • How should "deload" weeks affect the next-day rotation logic?
  • Should the Profile tab include muscle-group volume per week, not just per-exercise progression?
  • Onboarding skip — should we let returning users (already logged in) bypass it entirely?
  • Tablet / foldable layouts — we've designed only for 412×892 so far.
  • Plate calculator — common in serious lifting apps, not yet included.
Hand-off summary

The prototype is feature-complete for a first pass: onboarding, daily workout loop, progress review, and settings all work end-to-end on real interaction. Next biggest unlocks: real persistence layer, real GIFs/anatomy art, and decisions on superset / advanced-set patterns. The four workout-layout variants are explicitly meant to be A/B tested with real users — don't pick a winner from the office.
