Purpose

The user has just completed account/skip on the splash. This screen asks them to choose a training split — the recurring weekly structure for their workouts. The chosen split determines which exercises live on which day and seeds every subsequent screen.

Single-tap commit

One tap.
No "Continue."

Tapping any option immediately selects and advances. There is no separate Continue button — a 180 ms hold on the lime outline confirms the choice to the user before the screen transitions out.

The user's prior data (a PDF workout split) is surfaced as the recommended option, with a "From your PDF" badge. The other five options are popular, well-known programs for users without prior data.

Vertical structure

The screen is a vertical flex column with a fixed-height header, a scrollable body, and a fixed-height footer chrome (gesture nav). The phone frame itself is 412 × 892 px.

Horizontal grid

Two horizontal padding values are in use: 22 px for the top bar, and 20 px for everything below. This 2px difference is intentional — the IconBtn has internal padding that visually aligns its content with the 20px column.

All cards span 372 px wide (412 phone − 2×20 padding). Inter-card gap is 10 px. Cards are not full-bleed.

Safe areas

The status bar (38px) and gesture nav (24px) are inviolable. No content should overlap either.

06

Interaction

Primary gesture: single tap on any card

  1. Tap
    Touch on card. CSS active state immediately darkens the row (--surface-2).
  2. Set selected
    setSelected(opt.id) — card switches to selected state (lime border, lime tint, filled radio dot).
  3. 180 ms hold
    User sees the selection commit. Confirmation without explicit Continue button.
  4. Advance
    onNext() fires. The parent navigates to the next onboarding step. The current screen slides out left over 240 ms while the next slides in.

Secondary gestures

  • Back button (top-left IconBtn) — calls onBack(); returns to splash. Standard 36×36 tap target, no confirmation.
  • System back gesture (Android edge swipe) — should be wired to the same onBack() handler.
  • Scroll — if more options exist than fit (6+ cards on 412×892), the options region scrolls. Scrollbar is hidden but functional. Top bar and progress remain pinned.

What does NOT happen

Anti-patterns to avoid

Do not add a separate Continue / Confirm button — single-tap commit is intentional.
Do not add a long-press or context menu on cards.
Do not haptic-pulse on selection — the visual confirmation alone is the spec; haptics will be added centrally later.
Do not highlight the recommended option on mount as "pre-selected" — show it visually distinct (badge), but no card is selected until the user taps.

15

Accessibility

  • Group semantic. Wrap the option list in role="radiogroup" with aria-labelledby pointing at the title.
  • Each card: role="radio", aria-checked={isSel}, tabindex="0", focus ring (browser default OK).
  • Keyboard. Arrow up/down moves focus between cards; Enter or Space selects + advances. Esc calls onBack.
  • Hit area. Cards are ~96–140px tall. Far above the 48dp Android minimum.
  • Contrast. All text-on-surface combinations meet WCAG AA: --fg on --surface is 14.5:1; --fg-2 on --surface is 7.4:1; --accent-fg on --accent is 12.3:1.
  • Screen reader announcement on advance. Use an aria-live="polite" region: when the screen mounts, announce "Pick your split. Step 1 of 3. Six options available."
  • Reduced motion. If prefers-reduced-motion is set, skip the 180ms commit delay and advance immediately on tap.

Data model

The screen consumes one array, SPLIT_OPTIONS, defined in data.js. Each entry is rendered as one card.

window.SPLIT_OPTIONS = [
  {
    id:   '5day-illustrated',    // stable string id, used for selection
    name: '5 Day Illustrated',   // rendered as the big Anton title
    sub:  'Your PDF split',       // rendered below, 12px Inter
    days: ['Upper', 'Lower', 'Shoulders & Arms',
            'Legs (Quad)', 'Back & Chest'],
    recommended: true,           // shows the "From your PDF" badge
  },
  { id: 'ppl',         name: 'Push Pull Legs',
    sub: '3 or 6 day variants', days: ['Push', 'Pull', 'Legs'] },
  { id: 'upper-lower', name: 'Upper / Lower',
    sub: '4 day classic',    days: ['Upper', 'Lower', 'Upper', 'Lower'] },
  { id: 'bro',         name: 'Bro Split',
    sub: 'One muscle a day',  days: ['Chest', 'Back', 'Shoulders', 'Arms', 'Legs'] },
  { id: 'full-body',   name: 'Full Body',
    sub: '3x per week',       days: ['Full A', 'Full B', 'Full C'] },
  { id: 'custom',      name: 'Build my own',
    sub: 'Pick the days',     days: [] },
];

Rules

  • Order in the array determines display order.
  • Exactly one entry should have recommended: true at any time (currently the PDF-seeded one).
  • An entry with an empty days array shows no chips and no chip-row gap.
  • id is stable and used as both React key and persistence key.

State & props

Component signature

function SplitSelect({
  selected,     // string | null — currently selected split id
  setSelected,  // (id: string) => void
  onNext,       // () => void — advance to next onboarding step
  onBack,       // () => void — return to splash
}) { … }

Ownership

State for the selected id lives in the parent App component, not here. This screen is fully controlled. The parent persists it (eventually to local storage / cloud) once onNext fires.

Tap handler

onClick={() => {
  setSelected(opt.id);            // 1. mark card as selected
  setTimeout(onNext, 180);       // 2. 180ms hold, then advance
}}

The 180ms is the only piece of "magic timing" in this screen. Do not shorten below 120ms or the user will not see the selection register. Do not extend past 250ms or the screen will feel sluggish.

18

Edge cases

  • Empty SPLIT_OPTIONS. Render the screen chrome (top bar, progress, intro) and an empty state under the intro: "No splits available." This should not happen in practice — the array is hard-coded.
  • Long split name. The Anton title can wrap to two lines inside the card. Reduce the card padding-bottom only if the chips have wrapped to a third row.
  • Long sub. The sub paragraph allows up to 2 lines. Truncate with ellipsis after that — but the current copy is well within limits.
  • Many chips. Bro Split is the longest (5 chips). All fit within two lines at 320px card width. If a future split has 7+ days, the chip row will wrap to 3 lines — acceptable.
  • Build my own. No chips render. Card height is shorter (~80px). This visual asymmetry is intentional — it signals "this one is different."
  • Double-tap during commit delay. The 180ms window is short, but if the user double-taps, the second tap should be ignored. Guard with a committingRef on first click.
  • System back during commit. If the user hits back inside the 180ms window, cancel the setTimeout and run onBack. (Use useEffect cleanup or a ref'd timer.)
  • Returning to the screen. If the user goes back from step 2, selected should still be set to whatever they chose. The card should render in the selected state on mount.

Reference implementation

Drop-in React JSX. Assumes parent provides SPLIT_OPTIONS, TopBar, IconBtn (or your equivalents).

function SplitSelect({ selected, setSelected, onNext, onBack }) {
  const committingRef = React.useRef(false);

  const pick = (id) => {
    if (committingRef.current) return;
    committingRef.current = true;
    setSelected(id);
    setTimeout(() => { committingRef.current = false; onNext(); }, 180);
  };

  return (
    <div style={{ display: 'flex', flexDirection: 'column', height: '100%' }}>

      {/* 1. TOP BAR */}
      <TopBar
        title="Pick your split"
        sub="Step 1 of 3"
        left={<IconBtn icon="back" onClick={onBack}/>}
        big
      />

      <div style={{ padding: '0 20px 8px' }}>

        {/* 2. PROGRESS BAR */}
        <div className="progress" style={{ marginBottom: 14 }}>
          <div style={{ width: '33%' }} />
        </div>

        {/* 3. INTRO PARAGRAPH */}
        <p style={{ fontSize: 14, color: 'var(--fg-2)',
                    margin: '0 0 8px' }}>
          The split decides what muscles you train on which day. You can change this anytime.
        </p>

      </div>

      {/* 4. SCROLLABLE OPTIONS */}
      <div className="scrollable"
            style={{ padding: '8px 20px 20px' }}>
        <div role="radiogroup"
              style={{ display: 'flex', flexDirection: 'column', gap: 10 }}>
          {SPLIT_OPTIONS.map(opt => {
            const isSel = selected === opt.id;
            return (
              <div
                key={opt.id}
                role="radio"
                aria-checked={isSel}
                tabIndex={0}
                className="row-tap"
                onClick={() => pick(opt.id)}
                onKeyDown={(e) => (e.key === ' ' || e.key === 'Enter') && pick(opt.id)}
                style={{
                  background: isSel
                    ? 'color-mix(in oklch, var(--accent) 12%, var(--surface))'
                    : 'var(--surface)',
                  border: `1.5px solid ${isSel ? 'var(--accent)' : 'var(--line)'}`,
                  borderRadius: 14,
                  padding: 16,
                  position: 'relative',
                }}>
                {opt.recommended && (
                  <div style={{
                    position: 'absolute', top: -8, right: 14,
                    background: 'var(--accent)', color: 'var(--accent-fg)',
                    fontSize: 9, fontWeight: 700, padding: '3px 8px',
                    borderRadius: 100, textTransform: 'uppercase',
                    letterSpacing: '0.1em',
                  }}>From your PDF</div>
                )}

                {/* head: name+sub | radio */}
                <div style={{ display: 'flex',
                            justifyContent: 'space-between',
                            alignItems: 'flex-start' }}>
                  <div>
                    <div className="display" style={{ fontSize: 22, color: 'var(--fg)' }}>
                      {opt.name}
                    </div>
                    <div style={{ fontSize: 12, color: 'var(--fg-2)',
                                marginTop: 2 }}>{opt.sub}</div>
                  </div>
                  <div style={{
                    width: 22, height: 22, borderRadius: 100,
                    border: `2px solid ${isSel ? 'var(--accent)' : 'var(--fg-3)'}`,
                    display: 'flex', alignItems: 'center',
                    justifyContent: 'center',
                  }}>
                    {isSel && <div style={{ width: 10, height: 10,
                                          borderRadius: 100,
                                          background: 'var(--accent)' }} />}
                  </div>
                </div>

                {/* chips */}
                {opt.days.length > 0 && (
                  <div style={{ display: 'flex', flexWrap: 'wrap',
                              gap: 6, marginTop: 12 }}>
                    {opt.days.map((d, i) => (
                      <div key={i} className="chip"
                            style={{ background: 'var(--surface-2)',
                                    fontSize: 11 }}>
                        D{i + 1} · {d}
                      </div>
                    ))}
                  </div>
                )}
              </div>
            );
          })}
        </div>

        {/* 5. HINT LINE */}
        <div style={{ textAlign: 'center', marginTop: 16,
                    fontSize: 11, color: 'var(--fg-3)',
                    letterSpacing: '0.04em' }}>
          Tap a split to continue
        </div>
      </div>

    </div>
  );
}

Acceptance checklist

Implementation is complete when all of the following are observable on a 412×892 viewport:

  1. Visual parity
    Side-by-side with the rendered showcase in §01, no measurable difference in spacing, color, type weight, or radius.
  2. Five options render
    In the exact order: 5 Day Illustrated, Push Pull Legs, Upper/Lower, Bro Split, Full Body, Build my own. (Six total when "Build my own" is included.)
  3. Recommended badge
    "From your PDF" appears overhanging the top edge of the first card only.
  4. No pre-selection
    On first mount, no card is in the selected state.
  5. Single-tap advance
    Tapping any card selects it visually for ~180ms, then advances to the Method screen.
  6. No Continue button
    The bottom of the screen contains the hint line "Tap a split to continue" and nothing else.
  7. Back navigation
    Top-left arrow and system back gesture both call onBack.
  8. Scroll behavior
    If options overflow, the list scrolls. Top bar, progress, and intro stay pinned.
  9. Re-entry preserves selection
    If the user advances and returns, their previously chosen card shows the selected state.
  10. Keyboard
    Arrow keys move focus, Space/Enter selects + advances.
  11. Reduced motion
    When prefers-reduced-motion is on, the 180ms commit delay is skipped.
  12. Screen reader
    Cards announce as radio options with their name + sub. Group announces as "Pick your split, radio group, 6 items."
21

Open questions

  • Should "Build my own" route to a different next step than the curated options? Currently both go to the Method screen.
  • Is the 180ms commit hold long enough on lower-end devices, where the visual update may render late?
  • Should we add a quick-tip tooltip on first-launch above the first card ("Tap one to begin")? Not in scope for v1.
  • If a user signs in and we restore a previous split selection, do we still show this screen, or skip to home? Current behavior: always show, with prior choice pre-selected.
