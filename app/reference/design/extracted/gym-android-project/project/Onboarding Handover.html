Splash.

The first screen the user sees. Establishes brand tone (bold sport, lime accent, condensed display type) and offers two paths: cloud sync via account, or skip-to-local. 01

Purpose & behavior

The Splash screen is shown only once on first launch (or after the user clears their account/storage). It is the entry to the onboarding flow.

Two outcomes — same next step

  1. Sign up / Sign in — primary lime CTA. Triggers the sign-in flow (out of scope for this prototype; both buttons advance to the same next step here). Final implementation should open a cloud-auth modal or a separate auth screen.
  2. Skip — keep it local — secondary ghost CTA. Bypasses auth entirely. Data is stored on-device only.

Both buttons end up at the same next screen in this prototype: SplitSelect (Step 1 of 3). The branching auth flow is left for production implementation.

Design intent

The buttons are deliberately weighted to encourage account creation (the lime CTA is high-attention) but not block local-first use (skipping is one tap and clearly visible). The helper line below explains the trade-off in 18 words.

Layout & structure

The Splash uses a vertical flex column with justify-content: space-between: the top group (eyebrow + headline + subtitle) hugs the top of the safe area, and the bottom group (hero art + 2 CTAs + helper) hugs the bottom. The space-between is what gives the screen its editorial poster feel and what holds it up across screen heights.

Tap targets

  • Both buttons are full-width (less the 24px screen padding = ~364px wide on a 412 frame).
  • Primary CTA height ≈ 64px (22+22 padding + 20px line).
  • Ghost CTA height ≈ 50px (16+16 padding + 18px line).
  • Both well above the 44×44px minimum tap target.

Motion

  • Screen entrance: 240ms slide-in from right with fade (CSS keyframe slideIn). Applied via .screen-enter class on the root.
  • Button press: 120ms ease scale(0.98).
  • No idle animations on this screen. The headline does not animate in — it's there immediately.

Edge cases & rules

Text wrapping

  • Headline: hard-coded line breaks (Get / Gym / Done.) — do NOT allow CSS wrapping; the line breaks are part of the design.
  • Subtitle: max-width 280px, natural wrap. On narrow phones (<360px) it will wrap to 3 lines instead of 2 — that's fine.
  • Helper line: max-width 280px, centered, natural wrap. May wrap to 3 lines on smaller phones — that's fine.

Theme switching

The screen supports light theme automatically via the data-theme="light" CSS attribute on :root. Token values flip; no markup changes. The lime accent stays the same in both themes.

Branding tweaks

The accent color is controllable via the global Tweaks system. Five palettes ship: lime (default), ember, electric, blood, mono. The Splash automatically reflects whichever palette is active — no Splash-specific overrides.

Safe areas

The 80px top padding inside the splash content is in addition to the 38px status bar. Together they ensure the eyebrow sits ~118px below the top of the phone — well clear of the notch and any system overlay. The 12px bottom margin sits above the 24px gesture nav.

What NOT to add

  • No social-login buttons (Apple/Google) on this screen. Save those for a dedicated auth screen if needed.
  • No "Continue as guest" text — the second CTA already does that, more emphatically.
  • No version disclaimer in the helper text. The eyebrow at top is the only place version is shown.
  • No tagline above the headline. The lime eyebrow does that job.
07

Accessibility

  • Color contrast: lime on near-black gives 12.8:1 (AAA). FG on bg gives 17:1.
  • Focus order: primary CTA → ghost CTA. Helper line is non-focusable text.
  • Touch targets: both buttons exceed 44×44px minimum.
  • Screen reader labels: the headline should be marked up as <h1> in the production implementation (currently a styled div in the prototype). "Get Gym Done." is the page heading.
  • Reduced motion: if prefers-reduced-motion: reduce is set, the 240ms slide-in entrance should be skipped. Buttons should still get a brief press feedback.
  • Helper line: 11px is at the low end of legibility. The contrast is 4.6:1 (AA Large). If accessibility is paramount, consider 12px and lift to FG-2.
08

Assets & fonts

Fonts

  • Anton — Display headlines, all-caps numerals. Single weight (400). Self-hosted preferred; otherwise Google Fonts: family=Anton.
  • Inter — All body, eyebrow, button, helper text. Weights 400, 500, 600, 700. Google Fonts: family=Inter:wght@400;500;600;700.
  • JetBrains Mono — Placeholder labels and mono data (not used in production Splash text). Weight 500.

Images

The 180px hero is a striped placeholder. Replace with a real asset:

  • Recommended: a looping 4–6 second MP4 of an athlete mid-lift, ~720×500 source, dark-friendly composition. Falls back to a JPG poster.
  • Alternative: single hero photo, 1.85:1 aspect, optimized to ~80KB WebP.
  • Whichever asset is used, it must be clipped to border-radius: 18px and fill its container with object-fit: cover.

When recreating this screen

The Splash is a poster — treat it with that level of restraint. Don't add anything that isn't in this spec. Every element earns its place; padding sums and line-heights are tuned. If you find yourself wanting a third button, an animated headline, or a small illustration alongside the headline — stop and ask, don't add.
